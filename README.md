# Schedule Send CLI

Отложенная отправка писем из Thunderbird, управляемая из командной строки.

Кладёте задание в папку-очередь — расширение Thunderbird отправляет письмо в назначенное время. Без окон композера, без сторонних сервисов и без необходимости держать открытым что-то ещё, кроме самого Thunderbird.

## Зачем это нужно

Штатный Thunderbird умеет откладывать отправку только через черновик и сторонние дополнения. Если письма формируются скриптом, отчётом или внешней системой, удобнее не «кликать», а поставить задание текстом:

```bash
python send_job.py add --to "client@example.com" \
    --subject "Ежемесячный отчёт" \
    --body "Добрый день, отчёт во вложении." \
    --file "C:\Reports\report-2026-10.pdf" \
    --datetime "2026-11-01 09:00" \
    --from "me@company.ru"
```

## Как это работает

```
send_job.py add  ──►  queue/<id>.json  ──►  расширение Thunderbird (опрос раз в 10 с)
                                                    │
                    ┌───────────────────────────────┼───────────────────────────────┐
                    │                               │                               │
             нет времени                     время прошло                    время в будущем
                    │                               │                               │
              только черновик                отправка сразу                 scheduled/<id>.json
                                                                                    │
                                                                            таймер + черновик
                                                                                    │
                                                                            отправка в срок
```

1. Скрипт валидирует адреса, дату и вложения и пишет JSON-задание в папку `queue/`.
2. Там же создаётся `config.json` в профиле пользователя, по которому расширение находит эту папку.
3. Расширение читает задания, отправляет письма через внутренний API Thunderbird (`nsIMsgSend`) и переносит обработанные файлы в `done/` или `error/`.

Связь между скриптом и расширением — только файлы. Никаких сокетов, демонов и прав администратора.

## Требования

- Windows (пути и конфигурация рассчитаны на неё).
- Thunderbird 115 или новее.
- Python 3.8+ для скрипта.
- Настроенный в Thunderbird ящик с рабочим SMTP: расширение отправляет от имени существующей учётной записи.

## Установка

### 1. Расширение

1. `Tools → Add-ons and Themes → шестерёнка → Install Add-on From File…`
2. Выберите `dist/schedule-send-cli-0.6.6.xpi`.
3. Перезапустите Thunderbird.

Расширение не подписано Mozilla, поэтому при установке из файла нужен профиль, разрешающий неподписанные дополнения (или загрузка через `about:debugging` как временного дополнения — но тогда оно исчезнет после перезапуска).

### 2. Скрипт

Скопируйте `send_job.py` в любую постоянную папку — она же станет корнем очереди:

```
C:\Users\<вы>\Documents\schedule-send\
└── send_job.py
```

Один раз выполните:

```bash
python send_job.py where
```

Команда создаст `queue/`, `scheduled/`, `done/`, `error/` и `config.json`, по которому расширение найдёт очередь.

> Важно: очередь привязана к папке со скриптом. Не держите две копии `send_job.py` в разных папках — каждый запуск переписывает `config.json` на свою папку, и очередь «переезжает».

## Быстрый старт

```bash
# письмо одному адресату через 10 минут
python send_job.py add --to "user@example.com" --subject "Проверка" \
    --body "Тест" --datetime "2026-11-01 10:00"

# нескольким адресатам сразу, с копией и вложением
python send_job.py add --to "a@example.com, b@example.com" \
    --cc "boss@example.com" --subject "Отчёт" --body "Во вложении" \
    --file "C:\Reports\report.pdf" --datetime "2026-11-01 18:00" \
    --from "me@company.ru"

# куда всё складывается
python send_job.py where

# пакет заданий из JSON
python send_job.py batch examples/schedule.example.json
```

## Команды

| Команда | Что делает |
|---|---|
| `add` | Ставит одно письмо в очередь |
| `batch <file.json>` | Ставит пачку заданий из JSON-файла |
| `where` | Показывает пути очереди и конфига |

Параметры `add`:

| Параметр | Обязателен | Описание |
|---|---|---|
| `--to` | да | Получатели: `"a@x.ru, b@x.ru"` или `"a@x.ru" "b@x.ru"` |
| `--subject` | нет | Тема |
| `--body` | нет | Текст письма |
| `--file` | нет | Вложение; можно повторять |
| `--datetime` | нет | `"ГГГГ-ММ-ДД ЧЧ:ММ"`; без него создаётся только черновик |
| `--cc`, `--bcc` | нет | Копия и скрытая копия, тоже списками |
| `--from` | нет | Адрес отправителя — должен совпадать с учётной записью в Thunderbird |
| `--identity` | нет | Явный идентификатор identity вместо `--from` |

## Формат задания

Одно письмо — один JSON-файл в `queue/`:

```json
{
  "to": "a@example.com, b@example.com",
  "cc": "boss@example.com",
  "subject": "Отчёт",
  "body": "Добрый день, отчёт во вложении.",
  "files": ["C:\\Reports\\report.pdf"],
  "datetime": "2026-11-01 18:00",
  "from": "me@company.ru"
}
```

Пакетный файл — массив таких объектов, см. [examples/schedule.example.json](examples/schedule.example.json).

## Планирование: сейчас, прошлое, будущее

| Время в `--datetime` | Поведение |
|---|---|
| Не указано | Создаётся тихий черновик, отправки нет |
| В прошлом или «сейчас» | Скрипт предупреждает, письмо уходит немедленно |
| В будущем | Задание сохраняется, ставится таймер, создаётся черновик |
| Ближе 15 секунд к моменту обработки | Отправляется сразу, без таймера |

Thunderbird должен быть запущен в момент отправки — таймер живёт внутри него.

## Папки и состояния

| Папка | Содержимое |
|---|---|
| `queue/` | Задания, ожидающие обработки (расширение забирает их за ~10 секунд) |
| `scheduled/` | Запланированные задания до наступления времени |
| `done/` | Обработанные задания + `<имя>.result.json` со статусом |
| `error/` | Задания, на которых расширение упало, + текст ошибки |

Пустой `queue/` — норма, а не признак сбоя: файлы быстро переезжают в `done/` или `error/`.

## Диагностика

**Письмо не ушло, в `error/` пусто.** Проверьте, что Thunderbird запущен и расширение включено (`Ctrl+Shift+A`), затем посмотрите консоль ошибок (`Ctrl+Shift+J`, фильтр `ScheduleSend`): там видно каждую стадию обработки.

**`535 authentication failed`.** SMTP не принял пароль. Расширение отправляет письмо без окна, поэтому пароль должен быть сохранён в Thunderbird (галочка «Use Password Manager to remember this password» при вводе). Проверьте также имя пользователя и метод аутентификации в настройках исходящего сервера.

**`время ожидания соединения с сервером исходящей почты истекло`.** Сеть не достучалась до SMTP: VPN, прокси или фильтр. Расширение тут ни при чём — ручная отправка в этот момент тоже не пройдёт.

**Задание лежит в `queue/` и не обрабатывается.** Расширение не работает или смотрит в другую папку. Сравните путь в `config.json` с папкой скрипта: если рядом есть вторая копия `send_job.py`, запуск из неё переписал конфиг.

**Вложение не найдено.** Путь должен быть доступен процессу Thunderbird в момент отправки; сетевые диски отваливаются, если сессия не активна.

## Ограничения

- Thunderbird должен быть запущен во время отправки.
- Нет автоматических повторов при сбое SMTP: ошибка фиксируется в `error/`, черновик остаётся в «Черновиках».
- Очередь и пути рассчитаны на Windows.
- Учётная запись, от имени которой идёт отправка, должна существовать в Thunderbird; иначе письмо уйдёт от учётной записи по умолчанию.
