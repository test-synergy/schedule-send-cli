## Зачем это нужно

Thunderbird не умеет отправлять сообщение отложенно — такой функции у него нет. Письмо либо уходит сразу, либо остаётся в черновиках, пока его не отправят вручную.

Schedule Send CLI добавляет эту возможность: задание описывается текстом — получатели, тема, тело, вложения, дата и время, — а отправку в назначенный момент выполняет Thunderbird.

Отправлять можно массово. Одна команда `batch` ставит в очередь десятки писем, у каждого свои адреса, тема, вложения и время. Всё это делается из командной строки, без ручной работы в интерфейсе почтового клиента.

```bash
python send_job.py add --to "client@example.com" \
    --subject "Ежемесячный отчёт" \
    --body "Добрый день, отчёт во вложении." \
    --file "C:\Reports\report-2026-10.pdf" \
    --datetime "2026-11-01 09:00" \
    --from "me@company.ru"
```

## Как работает Schedule Send CLI

```
send_job.py add  ──►  queue/<id>.json  ──►  Schedule Send CLI (опрос раз в 10 с)
                                                    │
                    ┌───────────────────────────────┼───────────────────────────────┐
                    │                               │                               │
             нет времени                     время прошло                    время в будущем
                    │                               │                               │
              только черновик                отправка сразу                 scheduled/<id>.json
                                                                                    │
                                                                            таймер + черновик
                                                                                    │
                                                                            отправка в срок
```

1. `send_job.py` проверяет адреса, дату и вложения и записывает JSON-задание в папку `queue/`.
2. Там же создаётся `config.json` в профиле пользователя — по нему Schedule Send CLI находит эту папку.
3. Schedule Send CLI читает задания, отправляет письма через внутренний API Thunderbird (`nsIMsgSend`) и переносит обработанные файлы в `done/` или `error/`.

Связь между скриптом и Schedule Send CLI — только файлы. Никаких сокетов, служб и прав администратора.

## Требования

- Windows (пути и конфигурация рассчитаны на неё).
- Thunderbird 115 или новее.
- Python 3.8+ для скрипта `send_job.py`.
- Настроенный в Thunderbird ящик с рабочим SMTP: Schedule Send CLI отправляет от имени существующей учётной записи.

## Установка

### 1. Schedule Send CLI

Скачайте установочный файл: [**schedule-send-cli-0.6.6.xpi**](https://github.com/test-synergy/schedule-send-cli/releases/download/v0.6.6/schedule-send-cli-0.6.6.xpi) — тот же файл лежит в репозитории: [`dist/schedule-send-cli-0.6.6.xpi`](https://github.com/test-synergy/schedule-send-cli/blob/main/dist/schedule-send-cli-0.6.6.xpi).

1. Откройте установку дополнения:

   - английский интерфейс: `Tools → Add-ons and Themes → шестерёнка (⚙) → Install Add-on From File…`
   - русский интерфейс: `Инструменты → Дополнения и темы → шестерёнка (⚙) → Установить дополнение из файла…`

2. Выберите скачанный `schedule-send-cli-0.6.6.xpi`.
3. Перезапустите Thunderbird.

Schedule Send CLI не подписан Mozilla, поэтому при установке из файла нужен профиль, разрешающий неподписанные дополнения (или загрузка через `about:debugging` как временного дополнения — но тогда Schedule Send CLI исчезнет после перезапуска).

### 2. Скрипт `send_job.py`

Скачайте скрипт из релиза: [**send_job.py**](https://github.com/test-synergy/schedule-send-cli/releases/download/v0.6.6/send_job.py) — он же лежит в репозитории: [`send_job.py`](https://github.com/test-synergy/schedule-send-cli/blob/main/send_job.py).

Скопируйте его в любую постоянную папку — она же станет корнем очереди:

```
C:\Users\<вы>\Documents\schedule-send\
└── send_job.py
```

Один раз выполните:

```bash
python send_job.py where
```

Команда создаст `queue/`, `scheduled/`, `done/`, `error/` и `config.json`, по которому Schedule Send CLI найдёт очередь.

> Важно: очередь привязана к папке со скриптом. Не держите две копии `send_job.py` в разных папках — каждый запуск переписывает `config.json` на свою папку, и очередь «переезжает».

## Быстрый старт

```bash
# письмо одному адресату через 10 минут
python send_job.py add --to "user@example.com" --subject "Проверка" \
    --body "Тест" --datetime "2026-11-01 10:00"

# нескольким адресатам сразу, с копией и вложением
python send_job.py add --to "a@example.com, b@example.com" \
    --cc "boss@example.com" --subject "Отчёт" --body "Во вложении" \
    --file "C:\Reports\report.pdf" --datetime "2026-11-01 18:00" \
    --from "me@company.ru"

# куда всё складывается
python send_job.py where

# пакет заданий из JSON
python send_job.py batch examples/schedule.example.json
```

## Примеры

Все команды выполняются из папки, где лежит `send_job.py`. Thunderbird при этом должен быть запущен — Schedule Send CLI работает внутри него.

### 1. Самое простое: одно письмо одному адресату

```bash
python send_job.py add --to "client@example.com" --subject "Встреча перенесена" --body "Добрый день! Встреча перенесена на 15:00." --datetime "2026-11-06 09:00"
```

Задание попадёт в `queue/`, Schedule Send CLI заберёт его в течение 10 секунд, поставит таймер на 09:00 и создаст черновик. В 09:00 письмо уйдёт, а черновик исчезнет.

Ответ скрипта:

```
OK: job written -> C:\schedule-send\queue\20261105-182000-1a2b3c4d.json
Queue root: C:\schedule-send
To:  client@example.com
Scheduled for: 2026-11-06 09:00
Thunderbird должен быть запущен с Schedule Send CLI.
```

Если указать прошедшую дату, скрипт предупредит, а письмо уйдёт сразу.

### 2. Письмо с одним вложением

```bash
python send_job.py add --to "client@example.com" --subject "Отчёт за октябрь" --body "Добрый день! Отчёт во вложении." --file "C:\Reports\october-2026.pdf" --datetime "2026-11-06 10:00"
```

### 3. Письмо с несколькими вложениями

```bash
python send_job.py add --to "client@example.com" --subject "Документы по сделке" --body "Во вложении договор, счёт и акт." --file "C:\Reports\contract.docx" --file "C:\Reports\invoice.xlsx" --file "C:\Reports\act.pdf" --datetime "2026-11-06 10:30"
```

Флаг `--file` повторяется столько раз, сколько файлов. Пути с пробелами берутся в кавычки; сетевой диск (`I:\Clip\file.pdf`) допустим, но должен быть доступен в момент отправки. Файлы проверяются сразу: если файла нет или он пустой, задание не создастся и появится `ERROR`.

### 4. Письмо нескольким адресатам, с копией и скрытой копией

```bash
python send_job.py add --to "a@example.com, b@example.com" --cc "boss@example.com" --bcc "archive@example.com" --subject "Отчёт за октябрь" --body "Коллеги, отчёт во вложении." --file "C:\Reports\october-2026.pdf" --datetime "2026-11-06 11:00"
```

Все получат одно письмо: `a` и `b` видят друг друга в поле «Кому», `boss` — в копии, `archive` — скрыто.

Разделять адреса можно запятой или точкой с запятой, а также пробелом: `--to a@example.com b@example.com`.

### 5. Отправка от другого ящика

```bash
python send_job.py add --to "client@example.com" --subject "Счёт на оплату" --body "Счёт во вложении." --file "C:\Reports\invoice.pdf" --datetime "2026-11-06 12:00" --from "billing@company.ru"
```

Адрес в `--from` должен совпадать с учётной записью, настроенной в Thunderbird. Если такого адреса там нет, Schedule Send CLI отправит письмо от учётной записи по умолчанию.

### 6. Черновик на проверку, без отправки

Уберите `--datetime` — письмо не уйдёт, а появится в «Черновиках» готовым к правке:

```bash
python send_job.py add --to "a@example.com, b@example.com" --subject "Черновик отчёта" --body "Проверьте формулировки." --file "C:\Reports\october-2026.pdf"
```

Дальше можно дописать текст вручную и отправить, либо поставить задание заново — уже с `--datetime`.

### 7. Пачка разных писем из JSON

Один файл — много заданий, у каждого свои адреса, тема и время. Готовый образец: [`examples/schedule.example.json`](examples/schedule.example.json).

```bash
python send_job.py batch examples/schedule.example.json
```

Вывод по каждому заданию:

```
OK #1: 20261105-182000-aaaa1111.json -> client-a@example.com, client-b@example.com / Отчёт за октябрь
OK #2: 20261105-182000-bbbb2222.json -> client-c@example.com / Напоминание
Итого в очередь: 2
```

Формат элемента описан в разделе [Формат задания](#формат-задания).

### 8. Массовая рассылка из таблицы

Когда адресатов десятки, удобнее держать список в CSV. В репозитории есть готовый скрипт и образец таблицы:

- [`examples/bulk-from-csv.ps1`](examples/bulk-from-csv.ps1)
- [`examples/clients.csv`](examples/clients.csv)

```powershell
.\examples\bulk-from-csv.ps1 -Csv .\examples\clients.csv -Datetime "2026-11-01 09:00" -From "me@company.ru"
```

Скрипт читает колонки `email`, `subject`, `body`, `attachment` и вызывает `send_job.py add` для каждой строки, а в конце печатает, сколько заданий поставлено и сколько не прошло проверку.

Если нужно разослать одно и то же письмо всем сразу, достаточно одной команды со списком адресов:

```bash
python send_job.py add --to "a@example.com, b@example.com, c@example.com" --subject "Отчёт за октябрь" --body "Во вложении." --file "C:\Reports\october-2026.pdf" --datetime "2026-11-06 09:00"
```

Получатели увидят друг друга в поле «Кому». Чтобы адресаты не видели остальных, перечислите их в `--bcc`.

### 9. Проверить, что всё встало в очередь

```bash
python send_job.py where
```

Команда показывает пути очереди и конфига. Дальше загляните в `queue/`: свежий JSON лежит там недолго — около 10 секунд, — после чего переезжает в `done/` (успех) или `error/` (сбой, рядом появится файл с текстом ошибки).

### Частые ошибки в командах

| Сообщение | Причина | Что делать |
|---|---|---|
| `usage: … unrecognized arguments: b@example.com` | адреса разделены пробелом вне кавычек, а версия скрипта старая | взять `send_job.py` из этого репозитория или писать `--to "a, b"` |
| `Некорректный адрес … пропущена зона` | опечатка в домене: `user@company` вместо `user@company.ru` | исправить адрес |
| `Файл вложения не найден` | неверный путь или отключён сетевой диск | проверить файл в Проводнике |
| `Неверный формат даты/времени` | нужен `ГГГГ-ММ-ДД ЧЧ:ММ` | `--datetime "2026-11-06 09:00"` |
| `WARNING: время … уже прошло` | дата в прошлом | письмо уйдёт сразу; для расписания указать будущее время |

## Команды

| Команда | Что делает |
|---|---|
| `add` | Ставит одно письмо в очередь Schedule Send CLI |
| `batch <file.json>` | Ставит пачку заданий из JSON-файла |
| `where` | Показывает пути очереди и конфига |

Параметры `add`:

| Параметр | Обязателен | Описание |
|---|---|---|
| `--to` | да | Получатели: `"a@x.ru, b@x.ru"` или `"a@x.ru" "b@x.ru"` |
| `--subject` | нет | Тема |
| `--body` | нет | Текст письма |
| `--file` | нет | Вложение; можно повторять |
| `--datetime` | нет | `"ГГГГ-ММ-ДД ЧЧ:ММ"`; без него создаётся только черновик |
| `--cc`, `--bcc` | нет | Копия и скрытая копия, тоже списками |
| `--from` | нет | Адрес отправителя — должен совпадать с учётной записью в Thunderbird |
| `--identity` | нет | Явный идентификатор identity вместо `--from` |

## Формат задания

Одно письмо — один JSON-файл в `queue/`:

```json
{
  "to": "a@example.com, b@example.com",
  "cc": "boss@example.com",
  "subject": "Отчёт",
  "body": "Добрый день, отчёт во вложении.",
  "files": ["C:\\Reports\\report.pdf"],
  "datetime": "2026-11-01 18:00",
  "from": "me@company.ru"
}
```

Пакетный файл — массив таких объектов, см. [examples/schedule.example.json](examples/schedule.example.json).

## Планирование: сейчас, прошлое, будущее

| Время в `--datetime` | Поведение Schedule Send CLI |
|---|---|
| Не указано | Создаётся тихий черновик, отправки нет |
| В прошлом или «сейчас» | Скрипт предупреждает, письмо уходит немедленно |
| В будущем | Задание сохраняется, ставится таймер, создаётся черновик |
| Ближе 15 секунд к моменту обработки | Отправляется сразу, без таймера |

Thunderbird должен быть запущен в момент отправки — таймер работает внутри него.

## Папки и состояния

| Папка | Содержимое |
|---|---|
| `queue/` | Задания, ожидающие обработки (Schedule Send CLI забирает их за ~10 секунд) |
| `scheduled/` | Запланированные задания до наступления времени |
| `done/` | Обработанные задания + `<имя>.result.json` со статусом |
| `error/` | Задания, на которых Schedule Send CLI завершился ошибкой, + текст ошибки |

Пустой `queue/` — норма, а не признак сбоя: файлы быстро переезжают в `done/` или `error/`.

## Диагностика

**Письмо не ушло, в `error/` пусто.** Проверьте, что Thunderbird запущен и Schedule Send CLI включён (`Ctrl+Shift+A`), затем посмотрите консоль ошибок (`Ctrl+Shift+J`, фильтр `ScheduleSend`): там видно каждую стадию обработки.

**`535 authentication failed`.** SMTP не принял пароль. Schedule Send CLI отправляет письмо без окна, поэтому пароль должен быть сохранён в Thunderbird (галочка «Use Password Manager to remember this password» при вводе). Проверьте также имя пользователя и метод аутентификации в настройках исходящего сервера.

**`время ожидания соединения с сервером исходящей почты истекло`.** Сеть не достучалась до SMTP: VPN, прокси или фильтр. В такие моменты не проходит и ручная отправка из Thunderbird.

**Задание лежит в `queue/` и не обрабатывается.** Schedule Send CLI не работает или смотрит в другую папку. Сравните путь в `config.json` с папкой скрипта: если рядом есть вторая копия `send_job.py`, запуск из неё переписал конфиг.

**Вложение не найдено.** Путь должен быть доступен процессу Thunderbird в момент отправки; сетевые диски отваливаются, если сессия не активна.

## Ограничения

- Thunderbird должен быть запущен во время отправки.
- Нет автоматических повторов при сбое SMTP: ошибка фиксируется в `error/`, черновик остаётся в «Черновиках».
- Очередь и пути рассчитаны на Windows.
- Учётная запись, от имени которой идёт отправка, должна существовать в Thunderbird; иначе письмо уйдёт от учётной записи по умолчанию.
